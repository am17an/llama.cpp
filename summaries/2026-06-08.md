# llama.cpp daily summary -- 2026-06-08

Today's 9 commits are dominated by KV-cache work that followed the Gemma4 MTP merge, plus a handful of conversion and sampling fixes. The headline feature -- Multi-Token Prediction for Gemma 4 -- landed after a 2.5-week review and delivers >2x token-generation speedup on dense Gemma 4 models.

## Model support

- **Gemma4 MTP (Multi-Token Prediction)**: adds a speculative-decoding draft head built into the Gemma 4 model itself, enabling ~2x+ gen-speed improvement without a separate draft model. Touches 31 files across model, KV-cache, server, and conversion code. (#23398, `04eb4c4`)
- **Gemma4 conversion fix**: handle models with no audio encoder in `convert_hf_to_gguf.py`. (#24242, `f71af35`)

## KV Cache / speculative decoding

- **Avoid KV cells copies in `apply_ubatch`**: the `llama_kv_cells` copy that was introduced by Gemma4 MTP became expensive on some host configurations; patched out with a lightweight refactor. (#24277, `379ac66`)
- **Fix KV size mismatch when sharing cells**: `--fit` can shrink the target context below the draft default, causing an overflowed `ggml_view_4d` assert during graph reserve; now the assistant cache follows the source cache size. (#24267, `f0156d1`)
- **Fix vocab compatibility check in speculative path**: corrects an edge-case regression in draft-model vocab validation. (#24256, `8a091c4`)

## Conversion

- **Mistral-Medium-3.5-128B**: `params.json` explicitly sets `moe` and `llama_4_scaling` to `null`, breaking `key in dict` checks; replaced with `dict.get(key) is not None`. (#24268, `8a963fc`)

## Common / API

- **Relax sampler name matching**: `common_sampler_types_from_names` now always accepts both canonical (`top_k`) and alternative (`top-k`) names, case-insensitively; removes the now-unnecessary `allow_alt_names` flag from all call sites. Fixes a server UI issue where alternative names were silently rejected. (#23744, `9e3b928`)

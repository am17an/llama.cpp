# llama.cpp daily summary -- 2026-06-12

Today saw 10 commits land on upstream/master, led by a cluster of Vulkan backend improvements and a notable server-side cache correctness fix. The ggml subproject was bumped to v0.15.0, and tokenizer/vocab handling received a meaningful refactor.

## Vulkan / GPU

- **Fast path for contiguous UMA buffer transfers** (#23973, `fdc3db9`): When a 2D buffer read/write is contiguous in memory, a single bulk memcpy replaces row-by-row copying -- benchmarks show ~2.5x faster write throughput on UMA devices.
- **Medium matmul tile on Asahi Linux** (#24306, `1af154a`): Detects Apple AGX via the Honeykrisp Mesa driver ID and selects the medium tile size, yielding ~25% prefill speedup on M1 (pp512: 207 -> 259 t/s). **Notable perf win for Asahi/Linux-on-Apple-Silicon users.**
- **Build fix for eMesaHoneykrisp ifdef** (#24479, `4c65955`): Quick follow-up to #24306 fixing a CI/build regression.

## API / Server

- **Fix cache corruption with SWA models** (#24411, `db94854`): Skips KV-cache checkpoints beyond `pos_next`. Fixes silent correctness regression where models using sliding-window attention (e.g. Gemma 4) would produce corrupted/forgetful responses when a cached session was reused with a diverging prompt. **Correctness fix -- worth pulling promptly.**
- **Skip unused log lines in router mode** (#24463, `18ef86e`): Suppresses irrelevant log output when `llama-server` runs as a router, reducing noise.

## Vocab / Tokenizer

- **Refactor normalizer flags into options struct; add strip_accents** (#24371, `68f3066`): Cleans up flag handling in `llama-vocab` and adds a new `strip_accents` normalization option. Touches both C++ core and gguf-py.
- **Adopt leading TemplateProcessing token as BOS** (#24428, `1bfbdb1`): Improves BOS detection for models that use HuggingFace TemplateProcessing tokenizer configs.

## Build / DevOps

- **Docker: configurable GCC version for CUDA builds** (#24447, `1593d56`): Adds a build arg so users on older CUDA/Ubuntu combinations (e.g. CUDA 12.4 + Ubuntu 22.04 needing GCC 12) can specify the GCC version rather than being hard-locked to GCC 14.

## Misc

- **ggml v0.15.0 bump** (`17e59d6`) and **ggml sync** (`263cc04`): Routine subproject version and sync update.

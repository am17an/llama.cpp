# llama.cpp daily summary -- 2026-08-09

A focused day of 5 commits, split evenly between CUDA backend optimizations and server-side tool isolation/UX improvements. The Docker-based tool isolation feature (#26507) is the largest change and a notable new capability for agent use cases.

## CUDA/GPU

- **Fix thread/block count in quantized `cpy` kernel launches** -- kernels were launching with 1 thread/block (31 of 32 warp lanes idle); changing to `CUDA_CPY_BLOCK_SIZE` (64) threads yields up to 47x speedup on `q4_0->f32` copies, directly benefiting context shift with quantized KV cache. PR #26731, `69bf643`
- **Fuse `rms_norm + mul + rope` (+ `view + set_rows`) into a single CUDA kernel** -- combines two existing fusions into one pass; ~1% token-generation speedup on RTX 5090 with Qwen3 models. PR #26767, `687e778`

## API/Server

- **Add initial tool isolation support via Docker** -- new `--tools-runtime docker:<image>` flag proxies built-in tool calls into a Docker container, sandboxing filesystem and shell access away from the host. Includes Python test coverage and updated docs. Notable new feature for production/agent deployments. PR #26507, `dd2c7c4`
- **Only show working-directory UI chip when a tool actually uses it** -- tools now declare a `uses_cwd` capability; the WebUI chip and `/cwd` command appear only when at least one path-aware tool is enabled. Prevents confusing dead controls for setups using only tools like `get_datetime`. PR #26762, `18f7ad7`
- **`get_info` reports isolate working directory when a tools runtime is configured** -- previously returned the host server process CWD even when tools ran inside a container; now queries the isolate for its actual working directory. PR #26773, `7ba604f`

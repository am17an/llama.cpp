# llama.cpp daily summary — 2026-07-13

Today's activity focused exclusively on the server layer, with six merges fixing several correctness bugs in API compatibility, multimodal handling, and KV-cache management. No new features landed; the day was a solid round of bug-fixing and a vendor update.

## API/Server fixes

- **Fix per-request `reasoning_budget_tokens` and `reasoning_budget_message` being silently discarded** — `oaicompat_chat_params_parse` wrote these fields from the server default before the generic body-copy loop ran, so any caller-supplied override was ignored. Both fields are now read from the request body first. Includes new unit tests in `test-chat.cpp`. (#23116, `99f3dc3`)
- **Don't declare `--no-mmproj-auto` models as multimodal** — models with mmproj explicitly disabled were still advertised as supporting image/audio on the `/v1/models` endpoint. Fixed in `server-models.cpp`. (#25590, `8014d2c`)
- **Fix image blocks in `tool_result` dropped during Anthropic→OpenAI conversion** — `server_chat_convert_anthropic_to_oai()` silently discarded image blocks inside Anthropic `tool_result` content, breaking multimodal tool outputs. They are now converted to OpenAI `image_url` content parts; plain-text results remain unchanged. (#22536, `6b4dc21`)
- **Evict KV-cache checkpoints within `min-step` of each other** — improves checkpoint management to avoid keeping redundant nearby checkpoints. (#25472, `0c4fa7a`)

## mtmd

- **Fix silent prompt truncation on embedded NUL bytes** — `mtmd_input_text` used a bare `const char*` with no length, so a NUL byte in message content silently dropped everything after it (including the assistant marker). An explicit `text_len` is now threaded through to `llama_tokenize`. (#25548, `4114ba1`)

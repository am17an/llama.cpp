# llama.cpp daily summary -- 2026-07-05

Light day with 3 commits: two correctness bug fixes (one in the inference core, one in the ggml CPU backend) and a UI settings improvement. No breaking changes.

## Core / llama

- **Guard K/V rotation input when buffer is unallocated** (#25215, `a410713`): fixes a crash in DFlash speculative decoding where `set_input_k_rot`/`set_input_v_rot` called `ggml_backend_buffer_is_host()` on a NULL buffer, triggering `GGML_ASSERT(buffer)`. The same `&& ->buffer` guard already present for `kq_mask` inputs is now applied to the four k_rot/v_rot inputs. Reproducible on RDNA4 with quantized KV caches + DFlash draft; non-DFlash paths are unaffected.

## ggml

- **Fix broken CPU concat for quantized types** (#25247, `ef2d770`): `ggml_compute_forward_concat_any()` was multiplying element index `i0` by `nb00`/`nb10`/`nb0`, all equal to `type_size` for quantized types (e.g. 34 bytes for Q8_0), causing out-of-bounds reads/writes in `memcpy`. Fixed by iterating over whole quantization blocks instead of individual elements. Adds quantized-type coverage to `test-backend-ops`. Groundwork for DeepSeek V4 quantized KV cache (#25202).

## UI

- **Sync blocks for display/behavior settings via `--ui-config-file`** (#25132, `6658925`): adds missing sync wrappers so display and behavior settings can be configured at startup via the config file. Also removes the "enable thinking" setting from the UI (deferred to a follow-up refactor).

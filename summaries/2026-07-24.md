# llama.cpp daily summary -- 2026-07-24

A light but solid day: 6 commits across backend fixes, a notable CLI argument refactor, and ongoing AI-policy housekeeping. The most impactful change is a breaking-adjacent API overhaul that consolidates three memory-mapping flags into a single `--load-mode` argument.

## API / CLI

- **args: unify mlock/mmap/directio into `--load-mode`** (#20834, `e6dd0e2`) -- Replaces the separate `--mlock`, `--mmap`/`--no-mmap`, and `--direct-io` flags with a single `--load-mode` argument accepting `mmap`, `mlock`, and `dio` modifiers. Old flags still work but emit deprecation warnings. Touches `include/llama.h` (public API) and `llama-bench`; users and downstream tooling should migrate.

## CUDA / GPU

- **Fix external compilation of q1_0 MMQ** (#25778, `1425386`) -- Corrects a build regression when `mmq.cu`/`mmq.cuh` are compiled outside the main translation unit; affects quantized matrix-multiply performance paths for q1_0.

## Metal

- **Add f16 type support to leaky relu** (#25981, `c588c4f`) -- The Metal leaky relu kernel already handled 16-bit inputs internally but lacked a dispatch branch for f16 tensors; one-line fix extends coverage to match the f32 path.

## Hexagon

- **Fix Windows crash with op_poll enabled** (#26029, `c0bc859`) -- Resolves a crash on Snapdragon Windows targets when `GGML_HEXAGON_OPPOLL` is set; patches polling logic in `htp-drv.cpp`.

## Conversion

- **Fix non-MoE NomicBert GGUF conversion** (#25996, `d941f6e`) -- `find_hparam` was unconditionally looking up MoE-only keys (`num_local_experts`, `num_experts`), raising `KeyError` on non-MoE NomicBert models (e.g. CodeRankEmbed). Keys now scoped to the MoE branches only.

## Docs / Policy

- **Fix leftovers from AI usage policy update** (#26030, `da296d6`) -- Consistency cleanup in `AGENTS.md` and `CONTRIBUTING.md` following the policy introduced in #26012; no substantive policy changes.
